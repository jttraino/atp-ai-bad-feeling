# Keynote Synthesis Framework

This is the guiding brief handed to the model, alongside the raw station inputs, to produce the content of the Throne Room deck. It's checked into this repo so anyone can see exactly what shaped the synthesis, not just the output.

Note what this brief does **not** ask for: a deck, a slide, any HTML, or any formatting. The model is asked for content as structured data. The deck around it is generated by [`tools/build-deck/build_deck.py`](../build-deck/build_deck.py), which is code, and which rejects anything that doesn't match the schema below. That split is deliberate. The model does the part that needs judgment; code does the part that has exactly one correct answer.

## Event context (for the model)

This is the Throne Room, the closing keynote for ATP's "Your AI Program Has a Bad Feeling About This." It's an interactive workshop on why enterprise AI initiatives fail, run as the honest debrief nobody runs at their own company. Attendees split into five themed stations, each a guided discussion where the station sponsor put a list of roughly eight questions to the room and the room answered:

- **Sky City** (`sky-city`): infrastructure and integration challenges with third-party tools
- **Swamp Planet** (`swamp-planet`): technical debt and data quality issues
- **Ice Planet** (`ice-planet`): development-stage use cases stuck in limbo
- **Snow Monster Cave** (`snow-monster-cave`): unexpected costs and security vulnerabilities
- **Asteroid Field** (`asteroid-field`): compliance, legal obstacles, and scope creep

After all five run in parallel, the whole group reassembles. The keynote's job is to give everyone, including the roughly 100 people who weren't in a given station, the real, specific substance of what was said there, and then surface what connects across all five.

## Your input

You will be given five blocks, one per station. Each is labeled with its source:

- **`Source: transcript`** means a real recording of what the room actually said. Use it.
- **`Source: FALLBACK`** means no usable audio was captured. What you get instead is that station's pre-written question list and the answers we guessed at beforehand. Nobody in that room said these words.

## Task

Return **a single JSON object and nothing else.** No prose before or after, no explanation, no markdown fences.

```json
{
  "stations": [
    {
      "id": "sky-city",
      "lede": "One sentence framing what this room actually spent its time on.",
      "points": [
        {"t": "Short headline, under 120 characters", "d": "The specific thing that was said, with the real example, number, or disagreement attached."}
      ],
      "takeaway": "One line to leave the room with for this station."
    }
  ],
  "patterns": [
    {"t": "Short headline", "d": "The pattern, and which stations it showed up in."}
  ],
  "closing_line": "One line that ties the whole session together."
}
```

Schema rules. The structural ones are hard: break one and the whole run is rejected and the previous deck stands.

- `stations` must contain **all five**, exactly once each, using the `id` values listed above.
- Do **not** report which stations were on a transcript and which were on a fallback. You are told, above, so that you write appropriately, but the deck takes that from disk. Anything you say about it is discarded. We don't ask a model to report a fact we already know.
- `points`: 3 to 5 per station. `patterns`: 3 to 5 total.
- Length targets: `lede` 500, `takeaway` 280, `closing_line` 360, each `t` 150, each `d` 560. These protect the slide layout. Going over gets your text trimmed on a word boundary rather than rejected, so write to the target and don't pad.
- Plain text only in every field. No HTML, no markdown, no bullet characters. Don't use em dashes; the builder rewrites them to commas anyway, so write the comma yourself.

## Ground rules

- **Be specific.** Real examples, real numbers, real quotes, real disagreements. "Teams struggled with data quality" is worthless. "Three people said their vendor's confidence scores were uncalibrated and nobody could get the vendor to explain the threshold" is the point of the whole event.
- **Ground every point in the input text.** Do not invent examples, numbers, or quotes. If a station's input is thin, say less about it rather than padding it.
- **Never launder a fallback.** For a station marked `fallback`, stay close to what its questions establish was on the agenda, keep the language visibly more general, and do not write anything that implies a person in that room said it. The deck labels these on screen; your job is to not make the label a lie.
- **`patterns` is the reason this session exists.** It's the only part of the night nobody in any single room could have produced. Prefer a pattern that shows up in three stations over a sharper observation that only shows up in one.
- **No corporate buzzwords.** No "leverage," no "synergies," no "journey."
- Light Star Wars theming is fine, the station names invite it, but don't force a joke into every line.
